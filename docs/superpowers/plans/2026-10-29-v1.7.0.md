# v1.7.0 实施与联机验收记录

本文件执行用户已确认的屏幕自动检测、手机输入修复与远程防窥方案。正式发布以 UU 双端实测为门槛。

## 实现

- [x] 全部屏幕锁定开关，默认关闭；监视器设备接口标识迁移，保留离线选择。
- [x] 监听接入、移除、几何与 DPI 变化；零屏幕保持会话，重连后恢复覆盖。
- [x] 标准密码输入控件，单一提交入口，多屏只同步显示；不使用字符时间去重。
- [x] 独立的测试字符诊断窗口，仅在内存保留事件元数据，关闭即清空。
- [x] 远程允许列表独立保存；启动时不自动进入远程模式。
- [x] 全部本地屏幕纯黑；允许屏幕的遮挡排除采集，其余保持遮挡。
- [x] 验证密码后退出；再次启动软件或可选快捷键支持本地恢复。
- [x] 排除采集失败或全部允许屏幕断开，先创建普通全屏锁定再移除远程遮挡。

## 自动与原生检查

- 原有 67 项测试作为基线通过；新增后共 117 项测试通过，并逐项执行强制垃圾回收验证绘制生命周期。
- 独立的规范与质量审查通过。禁止远程使用的屏幕会接收并消耗输入，20ms 焦点检查负责将禁止屏幕上的前台应用焦点移到遮挡窗口；这是前台焦点重定向，不是操作系统级的零延迟输入隔离。
- 远程遮挡拒绝原生关闭请求，只有控制器在验证或安全切换后允许销毁。
- 实际 Windows 隐藏测试窗口的排除采集设置、读回与重置通过；未显示遮挡窗口。
- 当前三块显示器均能解析原生设备接口标识。Qt 友好名称通过经 DPI 校验的 Windows 显示源匹配。
- 修复回归测试暴露的绘制生命周期问题：每帧显式结束 QPainter，避免测试保留参数时发生原生回收崩溃。
- 测试版输出：`dist/v1.7.0-test/ScreenBlind.exe`。打包及隔离 APPDATA 下的启动检查通过。

### 本地鼠标干扰：来源诊断

- 用户确认现有逻辑正常，但本地鼠标可在允许屏幕操作应用，要求研究本地输入隔离。
- 经用户同意新增“通用 → 鼠标来源诊断”；test3 只诊断，不拦截，不改变远程模式行为。
- 两轮各 15 秒，由用户分别标记本地鼠标、手机 UU。汇总移动、按键和滚轮数量，以及 injected / lower_integrity 标记；不采集坐标、按键文本或落盘日志，关闭清空。
- 监听始终转发事件；超时、手动停止或关闭窗口卸载钩子。Windows 卸载异常时停止采集，并保留回调存活避免悬空指针。
- 128 项自动化测试通过；原生钩子安装及卸载检查通过。等待用户比较本地与 UU 标记后，再决定是否可实现本地鼠标屏蔽；未将 injected 标记认定为 UU 身份。

### test4：可选的本地鼠标屏蔽

- 用户实测：本地 6507 个事件全部 injected=0；手机 UU 329 个事件全部 injected=1，覆盖移动、按键及滚轮。
- 新增“远程模式下屏蔽本地鼠标（实验性）”，默认关闭；设置需退出远程模式后更改。
- 仅远程模式启用时安装拦截，屏蔽未标记为注入的鼠标事件，注入事件继续转发；不监听或屏蔽本地键盘。密码恢复期间仍保持鼠标屏蔽，验证成功退出后解除。
- 拦截安装失败触发普通全屏密码锁定；停止时先禁用拦截再卸载，卸载失败的回调保持存活并继续转发，避免影响恢复。
- 提取诊断与拦截共用的指针安全原生钩子生命周期。自动化不安装真实拦截钩子。
- 135 项测试通过，覆盖鼠标各类事件与注入标记、关闭状态转发、卸载失败、远程模式启停、安装失败以及设置保存；共用原生钩子的非拦截安装和卸载检查通过。
- test4 打包与隔离 APPDATA 启动检查通过；自动检查未启用真实鼠标拦截，用户当前实例未被操作。
- 该方案不认证 UU 身份，不提供系统安全边界，也不保证绕过低级钩子的输入路径或 Windows 因超时移除钩子时仍被拦截。新 UU 输入路径需重新验收。
- 待用户验证 test4：启用开关后本地移动、点击、滚轮无效，手机 UU 正常操作，本地键盘快捷键唤出密码框并恢复，退出模式后本地鼠标恢复。

### test5：锁定与恢复共用快捷键

- 用户要求 Ctrl+Alt+L 随状态自动判断。锁定快捷键在普通状态触发锁定，在远程模式唤出密码恢复框，在普通锁屏中不会直接解锁。
- 锁定与恢复字段可保存相同组合，仅注册一次并执行一次状态判断；设置窗口快捷键仍禁止与其冲突。恢复字段也可留空，直接使用锁定快捷键恢复。
- 托盘“立即锁定”保留远程模式切换到普通全屏密码锁定的行为；恢复仍需密码验证，未扩大未验证权限。
- test5 包含 test4 的可选本地鼠标拦截，仍待用户联机验收。
- 139 项测试通过，包含共用组合只注册和执行一次、设置快捷键冲突拒绝、普通/远程/已锁定状态分派；test5 打包及隔离 APPDATA 启动检查通过。

### test6：本地键盘屏蔽

- 用户确认本地鼠标移动、点击、滚轮无效，手机 UU 操作正常；本地恢复快捷键验证密码退出后，鼠标恢复。鼠标拦截联机验收通过。
- 用户进一步要求屏蔽本地键盘，仅保留 Ctrl+Alt+L。新增独立的实验性开关，默认关闭；沿用用户已配置的锁定/恢复组合，不设置新默认全局快捷键。
- 本地按键及修饰键统一吞掉，程序内部维护即时物理按键集合识别恢复组合，并排队唤出恢复框。注入事件使用键盘 LLKHF_INJECTED（0x10）放行，不混用鼠标标记。
- 普通密码输入仅在黑色恢复框可见且为 Windows 前台窗口时放行，Ctrl/Alt/Win 组合仍屏蔽。长按恢复键不会重复输入密码，取消或失去前台后继续屏蔽；已放行 Shift 的抬起事件仍交付，避免残留修饰状态。
- 不记录按键历史、扫描码或输入文本；退出模式先停用拦截再卸载。键盘监听安装失败转入普通全屏密码锁定。
- 无可用锁定/恢复快捷键时拒绝启用键盘拦截。Ctrl+Alt+Delete、安全桌面、绕过低级钩子的输入路径及 Windows 因超时移除钩子仍属于窗口方案边界。
- 等待用户验证 test6 的本地误触屏蔽、UU 数字/英文输入、Ctrl+Alt+L 恢复、取消后重锁及退出后键鼠恢复。
- 152 项自动化测试通过；原生键盘钩子仅转发模式的安装/卸载检查、test6 打包及隔离 APPDATA 启动检查通过。自动检查未启用真实键鼠拦截。
