# v1.7.0 实施与联机验收记录

本文件执行用户已确认的屏幕自动检测、手机输入修复与远程防窥方案。正式发布以 UU 双端实测为门槛。

## 实现

- [x] 全部屏幕锁定开关，默认关闭；监视器设备接口标识迁移，保留离线选择。
- [x] 监听接入、移除、几何与 DPI 变化；零屏幕保持会话，重连后恢复覆盖。
- [x] 标准密码输入控件，单一提交入口，多屏只同步显示；不使用字符时间去重。
- [x] 独立的测试字符诊断窗口，仅在内存保留事件元数据，关闭即清空。
- [x] 远程允许列表独立保存；启动时不自动进入远程模式。
- [x] 全部本地屏幕纯黑；允许屏幕的遮挡排除采集，其余保持遮挡。
- [x] 验证密码后退出；再次启动软件或可选快捷键支持本地恢复。
- [x] 排除采集失败或全部允许屏幕断开，先创建普通全屏锁定再移除远程遮挡。

## 自动与原生检查

- 原有 67 项测试作为基线通过；新增后共 117 项测试通过，并逐项执行强制垃圾回收验证绘制生命周期。
- 独立的规范与质量审查通过。禁止远程使用的屏幕会接收并消耗输入，20ms 焦点检查负责将禁止屏幕上的前台应用焦点移到遮挡窗口；这是前台焦点重定向，不是操作系统级的零延迟输入隔离。
- 远程遮挡拒绝原生关闭请求，只有控制器在验证或安全切换后允许销毁。
- 实际 Windows 隐藏测试窗口的排除采集设置、读回与重置通过；未显示遮挡窗口。
- 当前三块显示器均能解析原生设备接口标识。Qt 友好名称通过经 DPI 校验的 Windows 显示源匹配。
- 修复回归测试暴露的绘制生命周期问题：每帧显式结束 QPainter，避免测试保留参数时发生原生回收崩溃。
- 测试版输出：`dist/v1.7.0-test/ScreenBlind.exe`。打包及隔离 APPDATA 下的启动检查通过。

## 手机联机步骤（尚待用户测试）

### 2026-10-29 输入反馈与第二轮修正

- 用户确认豆包输入法输入数字正常；英文候选输入 `aa` 后提交只剩一个字符。暂不要求 GBoard 复测。
- 标准诊断实际收到两个 VK_PACKET（native=231）的 A 事件，中间有 Ctrl 按键。
- 本地复现：Qt 将带 Ctrl 的第二个 Unicode A 当作全选，留下一个字符。
- 第二轮仅将带控制修饰键的可打印 VK_PACKET 作为文本处理；真实物理 Ctrl+A 不变，不做字符时间去重。标准诊断框与密码控件共用适配器，日志追加修饰键字段。
- 122 项测试通过，包含真实快捷键保留、重复字符、事件接受状态回传。第二轮包：`dist/v1.7.0-test2/ScreenBlind.exe`，应用显示版本 `1.7.0-test2`。
- 待用户确认豆包标准框 `a`、`aa`、`aabb1122` 均能正确提交，再继续密码锁屏与远程防窥验收。

1. 从托盘退出旧版，运行新测试版本。原密码和设置保留，无需删除配置。
2. 先不锁屏。在“通用 → 远程输入诊断”中，分别在旧版对照和标准输入框输入 `aabb1122`。用手机原输入法和 GBoard 各试一次，观察标准框是否恰好 8 个字符；只用测试字符，不用真实密码。
3. 确认密码已设置，然后普通锁屏。点击唤出密码框后输入密码，检查字符数量和立即解锁；重复数字、退格和 Esc 均检查。
4. 远程模式前配置恢复快捷键，或保留再次启动 ScreenBlind 的入口。通过 UU 连接，选择允许屏幕并进入远程模式。
5. 本地观察全部屏幕均黑；手机端确认允许屏幕可见可操作，其余屏幕仍黑。若手机也黑，使用恢复入口验证密码退出，不认定为兼容。
6. 验证错误密码与取消不会恢复桌面；正确密码后恢复。尝试屏幕断开与重连，新屏幕默认禁止远程使用。

- [ ] 手机原输入法无重复字符。
- [ ] GBoard 无重复字符。
- [ ] 本地全部遮挡、远端按允许列表可用。
- [ ] 本地密码恢复与屏幕重连检查通过。
